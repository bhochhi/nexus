# Security policy

## Supported versions

This project is a proof of concept. Security fixes are applied only to the
latest tagged release and the current `main` branch. Earlier releases are not
supported unless their release notes say otherwise.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue, discussion, pull
request, or chat transcript. Use GitHub's private vulnerability reporting from
the repository's **Security** tab. If that option is unavailable, contact the
maintainer privately through the contact method on the maintainer's GitHub
profile and include only enough initial detail to establish a secure channel.

Include the affected release or commit, impact, reproduction conditions, and
any known mitigation. Do not include real member, customer, employee, account,
or credential data.

Receipt will be acknowledged when practical. Validation, remediation, and
disclosure timing depend on severity and maintainer availability; this project
does not promise a formal service-level agreement.

## Scope and safe use

The repository contains a development proof of concept with synthetic data and
mock integrations. It has not been certified for production financial use.
Deployers are responsible for authentication, authorization, secrets
management, network controls, dependency review, data classification,
monitoring, and applicable regulatory requirements in their environment.
